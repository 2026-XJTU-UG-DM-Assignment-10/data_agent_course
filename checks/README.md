# 各成员的独立自测入口

各成员分别实现 `check_A.py`、`check_B.py`、`check_C.py`、`check_D.py`。这些业务自测当前尚未实现，不放空文件冒充通过。

自测脚本需支持从项目根目录执行 `python checks/check_X.py` 及 `--integration`，失败时以非零退出码结束。使用真实业务函数和有意义的断言，输出验证范围，证据写入 `outputs/member_X/`。不要只打印 passed，不要将伪造返回用于检验自己本应实现的核心功能。

允许为其他成员尚未提供的依赖使用明确标记的测试替身；本人的核心函数不能被替身替代。测试替身仅存在于自测脚本或 `examples/role_X/`，不得成为生产流程中的静默降级。D 的最终集成检查必须使用真实模块。

| 自测 | 最少验证内容 |
| --- | --- |
| A | 正式数据准备结果达标且可追溯、来源组不交叉；检测原始缺失/重复/异常/格式问题，输入表未修改 |
| B | 规范化可重复执行；四类处理有效；填补只使用训练值；测试行数、标签、顺序不变；非法/全缺失列边界 |
| C | 规则模式零请求；拒绝测试摘要；非法计划和最多两次请求；日志与失败状态；管道接线；真实调用另列证据 |
| D | 干净小样本真实训练；未知类别不报错；固定矩阵顺序；排除 ID/标签特征；页面/CLI 的状态与错误逻辑 |

自测通过只证明它实际覆盖的范围。真实数据和模型的未执行项目必须留在交接记录中，不因本地测试通过而自动标记完成。

AI 使用账本按 `docs/AI使用记录规范.md` 维护。正式模块交接检查本人至少一条实际记录及其提示词引用；未知费用和内部请求数可保留 null。`python checks/check_ai_usage.py` 使用隔离的合成条目检查重复统计、未知值、费用口径和提示词路径，不代表发生了真实调用。

默认自测生成本地完整输出和 `evidence/X/` 中可提交的脱敏摘要，格式见 `evidence/README.md`。`--integration` 模式重新验证真实依赖，但只写 outputs，不修改已提交的摘要。真实缺少外部输入用退出码 2，检查失败用 1。
