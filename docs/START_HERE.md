# AI 与成员的统一入口

协作协议版本：2.0。业务接口版本：1.0。适用于任何能阅读文本的 AI，不依赖某个品牌、聊天历史或 AGENTS.md 的自动发现。

## 先明确角色

成员把 `prompts/A.md`、`B.md`、`C.md` 或 `D.md` 中对应的开工指令交给自己的 AI。一次只指定一个角色。角色尚未给出时，只需询问“我是 A/B/C/D 哪一位”，不要猜测并重写全项目。

## 必读顺序

1. 根目录 `AGENTS.md` 和 `README.md`：现状、边界、环境、实际仓库地址。
2. `docs/低沟通协作协议.md`：工作流程与完成标准。
3. `collaboration/roles.json` 中自己的条目：分支、文件归属、函数、离线输入、自测入口。
4. `docs/公共接口说明.md`、`src/schema.py`、`src/contracts.py`：固定业务契约。
5. 对应的 `docs/成员X_AI任务.md`：本角色的具体要求。
6. `handoffs/X.json`、`docs/handoff_X.md`、`docs/integration_log.md`：已做什么、退回什么、下一步是什么。
7. 涉及数据来源和课程交付物时查 `docs/数据处理智能体_AI开发任务书.md`。
8. 使用 AI 开发时必读 `docs/AI使用记录规范.md` 和本人的 `ai_usage/X/usage.json`；每段开发会话保存实际提示词和可获知用量，交接前核对，换模型不丢失历史记录。

下一次对话仍按这个顺序恢复，继续真实的未完成项，不因为换模型而重新搭建项目。

本人模块通过检查并完成交接后，即可报告“待评审”并结束当前角色任务，不必等待 D 上线。D 已接受且没有新任务时不重复修改；被退回时只修复明确问题，不接管其他角色。

## 文件访问能力不同怎么办

- 能读写工作区：直接读取文件、实现、运行验证，并写交接记录。
- 只能聊天：成员上传上述公共文件、对应角色文件和样本。AI 输出逐个文件的相对路径、完整内容及待执行命令；由成员应用到个人分支后实际执行检查。
- 想一次上传上下文：运行 `python scripts/build_ai_briefs.py`，把 `outputs/ai_briefs/member_X_AI_brief.md` 整份交给对应成员的 AI。它汇集当前规则、角色清单、接口、任务、交接和离线输入；无需逐个收集文件。后续有进展时重新生成，避免旧快照覆盖新工作。
- AI 没有执行环境：所有运行结论标记 `not_run`，不能写“已通过”。

课程任务书控制功能范围；公共 Python 文件和接口说明控制业务接口；本协议、角色清单与对应任务控制协作。当前用户的明确指令优先。发现矛盾时记录具体文件和最小修正建议，先推进不依赖该问题的工作。

## 唯一交付路径

```text
读取规则与本人状态
→ 检查个人分支与现有修改
→ 用共享样例独立实现本人模块
→ 实际运行本人自测
→ 更新本人 AI 账本、提示词、交接与证据
→ check_delivery --role X --submit
→ 提交个人分支
→ D 异步评审、合并、集成
→ 问题退回原负责人修复
```

工具不会自动切分支、合并、重置或推送。Git 操作按 README 和本协议执行。
