# PPT制作与课堂展示指南

本指南可直接交给PPT制作者和实际讲述者。内容以本交付包的报告、真实运行目录和验收证据为准，建议采用7页PPT配合约2分钟网页操作，整体7分钟。该时长是项目建议安排，不替代教师的课堂要求。

## 一、讲清楚项目解决了什么问题

一句话开场：我们面向固定Adult表格，把数据输入校验、训练摘要决策、工具清洗、分类评估和结果追溯组织为可运行的智能体流程，并提供可直接访问的网页。

按流程讲系统能力：输入阶段支持同结构CSV上传和无模型预检；检测阶段计算列级缺失和合法数值分布；模型只根据训练摘要选择白名单策略；工具执行清洗并保存训练状态；网页展示质量、理由、填补值和分类结果，支持导出与完整历史回放。各环节共同服务于规范输入、可解释决策、可核查执行和可复用结果这些目标。

讲述者可以按小组安排分段，也可以由一人串讲完整系统。成员工作表用于说明已完成工作，实际讲述安排和排练参与者另按事实记录。

## 四、两分钟网页展示步骤

课前先打开 **https://111.230.149.166/**，使用独立演示账号完成浏览器登录。提前安全取得口令，不把口令、API key或服务器管理员信息放入PPT或录屏。课堂电脑无需安装Python或建立SSH隧道。

1. **确认正式输入（约15秒）**：选择“本机CSV”，保持“使用演示数据”勾选，使用服务器已准备的正式Adult文件。不要勾选“查看合成页面示例（非真实运行）”。若展示上传，提前准备同包的train_dirty.csv和test_reference.csv，保留标签与两个来源字段。
2. **预检输入（约15秒）**：点击“预检输入（不调用模型）”，说明7140/3000行、14特征和来源隔离。预检中的“模型请求未调用”只描述预检阶段，实际请求看后续run_id及日志。
3. **创建新运行（约35秒）**：选择“llm · 真实模型”，仅点击一次“开始处理”。等待时解释模型接收训练摘要、白名单校验与工具执行，避免反复点击。若时间紧，直接使用已成功运行回放并明确说明。
4. **展示解释与质量（约25秒）**：指出本次run_id和结果模式，展开“列级质量与训练分布”“实际训练填补值（测试只应用）”，联系缺失率/偏度说明策略，查看四类问题前后变化。
5. **展示评估与下载（约20秒）**：展示Accuracy、Macro-F1及矩阵，下载处理后CSV或events日志。说明测试集没有删行，训练状态只从训练集学习。
6. **展示复用（约10秒）**：展开“回放历史成功运行（不创建新运行）”，说明它会保留原始ID与模式，且不新增模型调用。无需再次完整运行。

现场模型可能选择另一种合法类别策略，训练行数和Macro-F1也可能变化。以当前结果的run_id、策略和指标为准，不能把PPT中的已保存快照数字套到新运行上。上方模式选择器不会自动改变已有结果的模式，讲解时看结果区域的模式行。

## 五、课堂展示的关键

开场先交代数据问题与项目目标，随后用一条完整数据流串起实现。解释“大模型在哪里决策、代码在哪里执行、哪些统计只来自训练集”，比逐个罗列模块名更容易让听众理解。

把四类质量统计和分类指标分清：问题计数归零说明满足当前检测规则，不表示数据语义全部正确。Accuracy和Macro-F1来自保留的测试集，本次没有证明模型方案优于固定规则。

引用真实证据：演示run_id、清洗计划、审计数量和events日志；开发辅助AI与项目模型请求分开统计。截至本包，项目真实请求6次，输入5928/输出5652 token，费用未知。不要把聊天轮次当作内部调用次数，也不要把未知费用说成0元。

课前在讲台电脑原生打开PPT检查字体与排版，用教室网络完成一次网页登录及下载测试。实际排练时记录用时、讲述者、切屏顺序和故障处理；没有发生的参与或录屏不写成已完成。

## 六、网络与模型故障备用方案

| 现场情况 | 展示处理 |
| --- | --- |
| 模型请求等待过长或失败 | 说明当前状态，切换已保存成功运行回放，展示原始ID与时间，不称为现场新调用。 |
| 公网网页无法打开 | 使用包内PPT、截图、矩阵、summary和events讲解已保存实测，说明当前网络未完成现场运行。 |
| 必须现场执行且本地环境已准备 | 使用rules完成真实工具流程，并明确该模式没有请求模型；不要将规则结果称为模型结果。 |
| 上传预检拒绝 | 根据字段、标签或来源错误提示说明输入约束，切回已准备的正式文件，不在课堂临时修改元数据。 |

备用材料应在上课前下载到演示电脑，不能在断网后才取。课堂记录可以录像真实执行，也可以录像明确标识的历史回放，两者说明不同。

## 七、常见问题的简短回答

| 问题 | 回答要点 |
| --- | --- |
| 数据真实吗，为什么人工加问题？ | 数据来自UCI Adult，训练侧注入用于覆盖缺失、重复、异常和格式四类课程要求，原件与注入清单可查。 |
| 怎样避免数据泄漏？ | 先按来源组划分，测试不注入；模型只读训练摘要，填补、编码、标准化只从训练拟合。 |
| 大模型实际做了什么？ | 在限定选项中选择数值/类别填补策略并解释，工具执行固定流程，实际请求与回复保存在events和C业务账本。 |
| 为什么训练剩6998行？ | 本次先去重140行，填补后再去重2行；测试3000行始终保留。不是还原完整真值的保证。 |
| 为什么清洗后全0，Accuracy仍只有85.23%？ | 全0对应定义的四类质量问题，分类预测正确率是另一项评估。 |
| 模型比规则好吗？ | 本次Accuracy相同，模型Macro-F1略低，只能证明流程可运行、可解释和可追溯，不能宣称性能提升。 |
| 能处理任意CSV吗？ | 当前固定Adult的14特征、标签和来源字段，兼容编码/分隔符及列顺序，不自动猜测任意业务语义。 |
| 服务器复现是否完成？ | 已在独立Windows Server 2022/Python3.12.10安装环境、重建数据并跑通规则/真实LLM，后台服务重启及公网访问也已验证。 |
| 展示还有什么要做？ | 用教室网络实际登录，原生PPT检查并排练、录屏；手机实机、整机重启等以实际验证范围说明。 |

## 八、给PPT制作者的任务说明

请按本指南组织7页可编辑演示稿，建议7分钟，保留约2分钟网页操作。以report.md及主运行20261102T100936Z-a2090032为数据依据，将输入校验、训练分布决策、质量展示与历史复用放在完整工作流程中说明。成员页直接列每个人完成的工作。保留真实质量表、混淆矩阵和规则对照，引用可核查run_id与素材。讲者备注写清数据来源、解释和切屏步骤，网页登录口令私下提供。模型选择与指标按具体运行分别呈现，局限与未验证项如实保留。
