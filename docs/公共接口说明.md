# 公共文件与接口说明 v1.0

本文与 `src/schema.py`、`src/contracts.py` 共同构成四人共享约定。所有模块从 `src.schema` 导入公共类；不要在各模块重写一份字典结构或同名模型。

协作已升级为[低沟通协议 2.0](低沟通协作协议.md)，本业务接口保持 1.0。文件归属、自测入口和独立开发输入以 `collaboration/roles.json` 为准；冻结文件哈希见 `collaboration/contract_hashes.json`。所有模型先读[统一入口](START_HERE.md)。

公共类型使用 Pydantic 2.x。JSON 写文件用 `model_dump_json(indent=2)`，转为普通 JSON 可序列化字典用 `model_dump(mode="json")`，从 JSON 读取用 `model_validate_json(...)`。返回对象而不是 JSON 字符串，文件导出由流程层负责。

## 1. 公共文件的归属

| 文件 | 维护人 | 其他人怎么使用 |
| --- | --- | --- |
| `src/schema.py` | D 统一维护；A确认字段，B确认清洗统计，C确认模型和日志字段 | 直接导入常量、模型和异常，不复制定义 |
| `src/contracts.py` | D 统一维护 | 对照函数签名实现；里面的 Protocol 本身不执行业务 |
| `src/normalization.py` | B | A 的质量检测和 B 的清洗都调用同一个规范化函数 |
| `examples/` | D 汇总；各成员可提交新样本 | 共享的明确标记小样本，不冒充正式数据 |
| `requirements.txt`、README、配置示例 | D 汇总，成员报告自己新增的依赖 | 使用同一套环境，不各自固定冲突的版本 |
| 本接口说明 | D 合并更新 | 发现问题提出最小变更，继续开发不依赖变更的部分 |

接口需要改变时，在 `docs/interface_changes.md` 记录“旧接口、建议新接口、影响成员、原因”。由 D 一次性更新公共文件和说明，并同步给受影响成员；不要只改一份个人副本。

## 2. 数据表与 CSV

固定字段、顺序、类别顺序见 `src/schema.py`：14 个特征 + `income` + `_source_id` + `_group_id`，共 17 列。读入后可重排为 `CSV_COLUMNS`。

- `_source_id`：原始记录的稳定来源 ID；复制记录保留相同 ID。它不要求逐行唯一。
- `_group_id`：A 在问题注入前按规范化后的 14 个特征计算的稳定分组签名。建议用确定性序列化加 SHA-256，不能用跨进程不稳定的 Python `hash()`。
- 注入问题后保留原有 `_group_id`，不要根据已损坏的特征重算。训练和测试的 `_group_id` 集合必须不相交。
- 两个元数据字段仅用于审计和防止划分泄漏。分类器显式选择 `FEATURE_COLUMNS`，禁止使用“除了标签以外的所有列”。
- 标签固定为 `<=50K`、`>50K`，禁止把无效标签静默填补。准备脚本可排除并记录原始无效标签；运行阶段遇到无效标签报错。
- CSV 使用 UTF-8、英文逗号、有表头、`index=False`。运行读取建议 `pd.read_csv(path, dtype=str, keep_default_na=False)`，由公共规范化函数统一解释缺失。
- 保存处理后 CSV 时，数值列为数值类型，类别为字符串；元数据仍保留。函数不原地修改调用者的 DataFrame。
- 测试集转换保留原行顺序、标签和来源 ID，不删除行，不排序。

正式路径由 A 固定为：

```text
data/raw/adult.data
data/reference/train_reference.csv
data/reference/test_reference.csv
data/dirty/train_dirty.csv
data/manifests/split_manifest.csv
data/manifests/injection_manifest.csv
data/manifests/preparation_summary.json
```

`split_manifest.csv` 包含 `_source_id、_group_id、split`；`injection_manifest.csv` 包含来源 ID、字段、问题类型、旧值、新值。复制行用明确的 duplicate 事件记录。两份 manifest 不传给模型或分类器。

## 3. 所有成员共用的统计口径

质量问题可以重叠，**不能把四种计数相加当作问题总行数**。

| 字段 | 精确定义 |
| --- | --- |
| `row_count` | 当前输入行数，包含重复行 |
| `feature_count` | 固定 14，不计标签和两个元数据字段 |
| `missing_by_column` | 14 个特征逐列的原始缺失数量；包含实际空值和缺失标记，不包含随后因解析失败/非法数值产生的缺失 |
| `duplicate_rows` | 对公共规范化视图按 14 特征 + 标签判断重复，`keep="first"` 后的多余行数；元数据不参与 |
| `outlier_cells` | 规范化视图中成功解析但违反固定范围的数值单元格数，不包括原始缺失和解析失败 |
| `outlier_rows` | 至少一个上述异常单元格的行数，行不重复计数 |
| `format_issue_cells` | 因去外围空格、剥离允许单位或非缺失解析失败而需要格式处理的特征单元格数，同一格只计一次 |
| `parse_error_cells` | 非缺失值既不是合法数字，也不能按白名单后缀解析的数值单元格数；是格式问题的子集 |
| `numeric_summary` | 在规范化视图上排除缺失、解析失败和范围非法值后，计算训练摘要；至少含 count、mean、median、min、max、std，无法计算用 null |

`dtypes` 描述传入数据的实际类型，不将 CSV 读出的字符串列全部算成格式错误。普通数字字符串如 `"40"` 不算格式问题；`" 40 "`、`"40 hours"` 算。`"999 hours"` 同时有格式问题和范围异常。

检测不得修改原表，也不把注入真值作为检测答案。A 可用 manifest 离线核查构造，但不能把它输入 `profile_data`。

## 4. B 先交付的公共规范化函数

```python
normalize_frame(df) -> tuple[DataFrame, NormalizationAudit]
```

位置：`src/normalization.py`。B 第 1 天优先交付，A 的 profiler 直接调用它。函数行为：

1. 检查固定列、标签和元数据；返回副本，保留行顺序与索引。
2. 将实际空值和 `MISSING_TOKENS` 中的字符串标记识别为缺失；字符串标记比较不区分大小写。
3. 类别字段只去外围空格，保留原有类别大小写；固定填充值为 `Unknown`。
4. 数值字段去外围空格，只允许年龄的 year/years、周工时的 h/hour/hours 后缀，后缀比较不区分大小写。
5. 合法数字转为有限数值；非缺失解析失败值转为缺失并计数。无穷大等非有限值按解析失败处理。
6. 保留成功解析的范围异常数值，供 A 检测、B 后续置空。这里不填补、不去重、不训练任何参数。

同样数据重复规范化应得到一致结果，已规范化数据的再次处理不产生新的格式修改计数。不要在 profiler 和 cleaner 里分别维护不同的正则或缺失规则。

## 5. 六个业务接口

### A：质量检测

```python
profile_data(df, *, dataset="train", stage="before") -> QualityReport
```

- 位置：`src/profiler.py`。
- 使用规范化副本计算质量问题，原始缺失与格式统计仍按第 3 节口径。
- `missing_by_column` 和 `dtypes` 应包含全部 14 个特征；没有问题填 0。
- `numeric_summary` 包含六个数值字段，供 C 制定计划。
- `dataset` 和 `stage` 写入返回对象，避免将测试摘要误传给模型。

### B：拟合并清洗训练集

```python
clean_training_data(train_df, plan) -> (clean_df, cleaning_state, audit)
```

- 位置：`src/cleaner.py`；返回 `DataFrame、CleaningState、CleaningAudit`。
- 顺序：规范化 → 去完全重复 → 非法数值置空 → 从训练集计算填补值 → 填补 → 最终重复复查。
- 填补可能让原本不同的记录变成完全相同；最终再去重一次，分别记录前后两轮删除数量。
- 数值填补值来自合法的训练观测；某数值字段完全没有合法观测时，报 `DataValidationError`，不随意造值或删字段。
- 类别众数并列时按字符串排序取第一个；该类别列全缺失时使用 `Unknown` 并写入 warning。
- 清洗后六个数值字段必须为数值型；14 个特征无未处理缺失、范围非法值和完全重复。
- `CleaningState` 保存六个数值填补值、八个类别填补值、计划和固定字段顺序；无需 pickle。
- `audit.input_rows - audit.output_rows` 必须等于两轮去重总数。不要承诺其余质量计数可以直接相加。

### B：只转换测试集

```python
transform_test_data(test_df, cleaning_state) -> (clean_test_df, audit)
```

- 位置：`src/cleaner.py`；不得重新计算填补值，也不得改变传入 state。
- 执行相同规范化与非法值置空，只使用 state 中的训练填补值；不去重、不删除行。
- 返回 `CleaningAudit.dataset="test"`，输入输出行数相同，两轮删除数均为 0。

### C：获取处理计划

```python
get_cleaning_plan(train_report, *, mode, llm_client=None, event_sink=None) -> CleaningPlan
```

- 位置：`src/agent.py`；只接受 `dataset="train"、stage="before"` 的报告。
- 规则模式直接返回规则计划，不能请求模型。
- 模型模式要求可用客户端，调用 `generate_plan(summary, feedback=...)`；最多两次，包括修正。
- `LLMClientProtocol` 见 `contracts.py`，返回 `LLMReply`，包含原始文本、真实模型、参数及可获知的用量。
- `mode`、接口版本由本地代码根据真实调用上下文填入，不能盲信模型自报。JSON 其余字段用 `CleaningPlan` 校验，拒绝多余字段或不支持的策略。
- `steps` 固定顺序；可执行决策为均值/中位数、众数/Unknown，理由必须非空。
- 记录提示词、原始返回、参数、校验错误和修正过程；密钥和鉴权请求头不能写日志。

`event_sink` 是 C 的日志适配入口，签名为 `(event_name: str, payload: dict) -> None`。未提供时允许独立单测，但真实流程必须提供。大对象先转 `model_dump(mode="json")`；日志由 C 补运行 ID、序号、模式、时间和状态。

### D：分类与评估

```python
train_and_evaluate(clean_train, clean_test, *, output_dir, seed=42) -> ClassificationResult
```

- 位置：`src/classifier.py`；明确选择 `FEATURE_COLUMNS` 和 `TARGET_COLUMN`。
- 特征标准化和独热编码只在训练集拟合，测试阶段未知类别使用 `handle_unknown="ignore"`。
- 逻辑回归一次训练即可；训练缺少某一标签、仍有缺失/非法数值等问题时明确报错。
- 固定类别顺序 `("<=50K", ">50K")`；混淆矩阵行是真实类别、列是预测类别。
- Accuracy 和 Macro-F1 使用 0–1 数值，页面展示时再转百分比；报告必须写明是 Macro-F1。
- 把混淆矩阵图片写到传入目录，返回 `ClassificationResult`；不返回原任务书早期版本中的 `(model_bundle, metrics)` 元组。
- 不设 5,000 行硬限制，允许小样本联调；正式规模由 A 准备脚本和 D 验收脚本检查。

### C：总流程；D 调用

```python
run_pipeline(train_path, test_path, *, mode, output_dir="outputs", seed=42,
             llm_client=None) -> RunResult
```

- 位置：`src/pipeline.py`，由 C 维护。D 的页面/CLI 只调用该接口，不再实现第二套流程。
- `output_dir` 是输出根目录。C 生成时间戳加随机后缀的 `run_id`，实际输出为根目录下 `<run_id>/`，避免重绘覆盖结果。
- 读取 CSV → 校验来源组不重叠 → 检测训练集 → 获取计划 → 清洗训练集 → 复查 → 转换测试集 → 分类 → 导出。
- 返回对象的 `output_dir` 为实际运行目录绝对路径；`artifacts` 中每个值为相对于该目录的文件路径。
- 运行失败也要保留事件日志，返回 `status="failed"`、明确错误和已经生成的文件，不伪造指标。
- 规则模式不得创建真实调用事件；模型模式失败不得静默返回规则模式成功。
- C 在真正的工具函数调用前后统一写日志，A/B/D 纯业务函数不各自维护一份 events 文件。

## 6. 文件导出归属与日志

C 的 pipeline 统一导出：`quality_before.json、quality_after.json、cleaning_plan.json、cleaning_state.json、train_processed.csv、test_processed.csv、metrics.json、summary.md、events.jsonl、audit_train.json、audit_test.json、run_result.json`。其中 quality_before/after 指训练集；测试集审计使用独立文件。D 的分类模块只负责生成混淆矩阵图并返回其路径。

关键日志事件可统一为 `run、profile、llm_request、plan_validation、clean_train、transform_test、train_evaluate、export`。每项使用 started/succeeded/failed 或 info 状态，序号从 1 递增，时间保存带时区的 UTC；页面可转换本地时间。

`LLMReply.cost` 等未知字段使用 null。已知成本必须同时记录币种和来源；不记录鉴权信息。`summary.md` 说明当前模式及真实结果，不能把规则运行写成“模型自主选择”。

## 7. 异常边界

| 场景 | 模块应抛出的公共异常 | pipeline 怎么处理 |
| --- | --- | --- |
| 缺列、无效标签、元数据错误、数字字段全不可用 | `DataValidationError` | 失败，记录可理解的原因 |
| 计划非法、两次修正仍失败 | `PlanValidationError` | 失败，保留返回与校验记录 |
| 凭据缺失、鉴权失败、网络/服务错误 | `ModelCallError` | 失败，页面提示可另选规则模式 |
| 未预料的程序错误 | 原异常 | 记录 internal_error 和诊断信息，页面不泄露凭据 |

单个普通脏数值不是整个运行失败的理由，可规范化为缺失再按规则处理。失败状态与真实质量问题分开。

## 8. 最小联调调用示例

以下是成员代码完成后的调用方式，交接包本身尚不包含这些实现：

```python
from pathlib import Path
import pandas as pd
from src.schema import CleaningPlan
from src.profiler import profile_data
from src.cleaner import clean_training_data, transform_test_data
from src.classifier import train_and_evaluate

train = pd.read_csv("examples/train_small.csv", dtype=str, keep_default_na=False)
test = pd.read_csv("examples/test_small.csv", dtype=str, keep_default_na=False)
plan = CleaningPlan.model_validate_json(
    Path("examples/plan_rules.json").read_text(encoding="utf-8")
)
before = profile_data(train, dataset="train", stage="before")
clean_train, state, audit_train = clean_training_data(train, plan)
clean_test, audit_test = transform_test_data(test, state)
after = profile_data(clean_train, dataset="train", stage="after")
Path("outputs/local_check").mkdir(parents=True, exist_ok=True)
metrics = train_and_evaluate(
    clean_train, clean_test, output_dir="outputs/local_check", seed=42,
)
print(before.model_dump(mode="json"))
print(after.model_dump(mode="json"))
print(metrics.model_dump(mode="json"))
```

第 1 天就共享本例、小样本和公共模型；第 4 天让它在真实业务实现上跑通。真实模型模式在此基础上由 C 接入，不阻止 A/B/D 先开发。
