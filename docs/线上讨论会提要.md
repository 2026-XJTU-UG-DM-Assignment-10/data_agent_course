## 一、项目目标与现状（3 分钟）

目标：在 10 个开发日内完成可运行、可解释、可复现的课程项目，展示前完成统一排练。

- 已具备：组织仓库、五个分支、公共接口、独立开发样例、四份 AI 开工资料、交接与检查工具。
- 本轮开发：正式数据、质量检测、清洗工具、真实模型接入、分类、页面及正式材料。
- 功能范围：一个数据集、一个智能体、一个分类器、一个展示页面。

## 二、实现方案（5 分钟）

| 项目 | 方案 |
| --- | --- |
| 数据 | UCI Adult；抽取 10,000 条参考记录；保留 14 个特征 |
| 任务 | 判断收入属于 ≤50K 或 >50K |
| 数据问题 | 缺失、重复、异常、类型或格式不一致 |
| 智能体 | 根据训练摘要选择处理方法，输出 JSON 计划，调用 Python 工具 |
| 清洗 | 规范格式、去重、非法值置空、填补、处理后复查 |
| 分类 | 逻辑回归；输出 Accuracy、Macro-F1、混淆矩阵 |
| 页面 | Streamlit；展示策略、前后统计、分类结果和下载入口 |

**CSV → 质量检测 → 模型计划 → 工具清洗 → 结果复查 → 分类 → 导出**

开发顺序：规则流程 → 真实模型 → 页面与展示材料。每次运行最多请求模型 2 次；原生问题和人工注入问题分别记录，随机种子固定为 42。

## 四、检验与交付标准（5 分钟）

| 检查项 | 最低标准 |
| --- | --- |
| 数据规模 | 清洗后训练数据 ≥5,000 条，保留 14 个特征 |
| 四类问题 | 确实存在；有检测、处理前后统计和修改记录 |
| 智能体 | 至少 1 次真实模型生成计划并执行，保留调用与工具日志 |
| 分类 | 输出真实 Accuracy、Macro-F1、混淆矩阵；不设精度或提升门槛 |
| 数据边界 | 来源组不交叉；参数只从训练集学习；测试行数和标签不变；ID 与标签不进入特征 |
| 错误与复现 | 非法计划会被拒绝；失败与修正可追踪；另一位组员可按 README 运行 |
| AI 使用记录 | 各人保存模型、提示词、参数、次数和费用；开发与项目运行分开，未知项明确保留，D 合并统计 |
| 正式材料 | 报告、源码、数据、PPT、个人贡献说明、运行记录六项齐全 |

报告目标 5–6 页，最多 10 页；PPT 6–7 页，汇报 7 分钟、问答 3 分钟。示例数据、示例指标和模拟模型返回只用于开发，正式验收使用真实数据与调用。

## 五、协作方式与排期（6 分钟）

**个人分支开发 → 本人自测 → 自动交接检查 → 待评审 → D 异步集成或退回**

- 接口保持 v1.0，各人主要修改本人文件；公共变更由 D 统一发布。
- 上游未完成时先用共享样例独立开发；正式集成使用真实模块。
- 交接使用 Markdown、JSON 和脱敏验证摘要，不依赖口头说明。
- 第 4、6、8 天由 D 执行技术检查，不要求全员在线。
- 全体交流仅保留开工确认与展示前排练；阻塞或预计延期时再单独同步。
- 四人使用各自 GitHub 账号；直接推送需要仓库 Write 或更高权限。
- 每段 AI 开发会话更新本人的 `ai_usage/X/` 账本及提示词，交接时核对；C 统一登记项目运行请求，D 自动汇总，无需每天集中填报。
