## 二、任务与实现（5 分钟）

### 1. 任务范围

- 数据：UCI Adult，固定抽取 10,000 条参考记录，14 个特征，收入高低二分类。
- 质量问题：缺失、重复、异常、类型/格式不一致。
- 智能体：根据检测摘要选择清洗策略，再自动调用 Python 工具。
- 模型：只用逻辑回归。
- 展示：一个 Streamlit 页面，可查看前后质量统计、清洗计划、分类指标和日志。

正式训练数据清洗后仍应不少于 5,000 条，保留 14 个特征。原始问题和人工注入问题分开说明，构造过程使用固定随机种子并留存记录。

### 2. 一条完整流程

```text
训练/测试 CSV
  → 检测训练数据的四类问题
  → 大模型读取训练摘要，输出 JSON 计划
  → 校验计划，调用清洗工具
  → 复查训练数据；用训练集参数转换测试数据
  → 训练逻辑回归并评估
  → 展示结果，导出数据和日志
```

大模型至少选择“均值/中位数填补”“众数/Unknown 填补”，并说明理由。Python 负责实际计算和清洗。规则模式用于前期联调；正式智能体演示至少保留一次真实模型成功运行记录。

初版每次运行最多两次模型请求，包含一次格式修正。API 密钥保存在本地环境变量，不提交到仓库或写入日志。

### 3. 实现顺序

先以固定规则跑通本地流程，再接真实模型，最后补页面和展示材料。暂不增加多智能体、聚类、多分类器、复杂调参、数据库或部署。

A/B/C/D 是职责代号，会上按成员技能和意愿认领并填入姓名。

| B：规范化与清洗 | 待填写 | 格式规范化、去重、异常处理、缺失填补、测试集转换 | 共享规范化函数、清洗数据、参数与修改统计 |
| C：智能体与总流程 | 待填写 | 规则/模型计划、API 适配、调用其他模块、日志与导出 | 规则流程，再补真实模型流程 |
| D：分类与展示 | 周锦晨 | 逻辑回归、指标、页面、CLI、公共文件与最终集成 | 分类函数，再补完整页面 |

D 负责汇总和合并；各模块的问题由对应成员修复。每人同时提供本人模块的报告文字、真实结果、PPT 素材和答辩准备。

需要全员遵守的公共约定：

1. 使用 `src/schema.py` 的统一字段和返回对象，不各写一套。
2. A 的检测、B 的清洗共用 B 的 `normalize_frame`，B 优先交这个函数。

4. 填补、标准化、编码只在训练集学习；测试集不删行、不改标签。
5. 来源 ID 和分组 ID 用于追踪，不进入分类特征。
6. 公共接口需要改动时，由 D 汇总并同步给受影响成员。

完整签名以 [公共接口说明](公共接口说明.md) 为准。独立任务见 [A](成员A_AI任务.md)、[B](成员B_AI任务.md)、[C](成员C_AI任务.md)、[D](成员D_AI任务.md)。

## 四、怎样检验完成（5 分钟）

不设 Accuracy、F1 或性能提升门槛；要求结果真实、流程完整、方法可解释。

| 检查项 | 会议认可的最低完成证据 |
| --- | --- |
| 数据规模 | 正式训练数据清洗后至少 5,000 条，至少 10 个特征字段；本项目保留 14 个 |
| 四类问题 | 问题数据确实包含四类问题，检测结果、处理前后统计和修改数量可查 |
| 清洗效果 | 已定义的非法值、缺失、格式错误得到处理，训练集完全重复得到清理 |
| 智能体 | 真实模型返回计划与理由，并有工具执行日志；规则模式明确标记 |
| 分类 | 真实输出 Accuracy、Macro-F1、混淆矩阵和测试样本数 |
| 数据边界 | 训练/测试来源组不交叉；参数只从训练集学习；测试行数和标签不变 |
| 错误处理 | 非法计划会被拒绝；修正和失败有记录；受控故障测试明确标注 |
| 可复现 | 另一位组员按 README 能运行；凭据缺失与规则运行状态说清楚 |
| 交付材料 | 报告、源码、数据、PPT、个人贡献说明、真实运行记录齐全 |

验证分三层进行：

1. 每人用公共小样本检查自己的模块，交一条运行命令和真实结果。
2. 规则模式连接所有模块，确认输入能走到分类结果及文件导出。
3. 使用正式数据和真实模型跑一次完整演示，再换组员电脑或新环境复现。

现有 `scripts/check_contracts.py` 只检查公共类型和微型样本。完整业务验证由各成员开发后补齐，不能用该检查代替端到端验收。

## 五、Git 协作与排期（6 分钟）

### 1. 最小 Git 工作方式

- 一个组织仓库，每人一个成员分支，main 保留集成版本。
- 队友使用自己的 GitHub 账号。公开仓库可直接克隆，推送前需确认已获得 Write 或更高权限。
- 每人主要修改本人负责文件；完成一小块后提交到自己的分支。
- 提交前检查修改列表，上传后把分支名、运行方法和结果交给集成人，由其检查合并。
- 收到主分支更新通知时，先提交自己的修改，再拉取并合入最新 main；冲突由集成人和文件归属人共同处理。
- 不要求每天全员开会或联调。完成交付时更新 Markdown/JSON 记录并运行交付检查；只有外部输入缺失、契约冲突或预计延期等真实阻塞才额外沟通。

首次加入，以 B 为例：

```powershell
git clone https://github.com/2026-XJTU-UG-DM-Assignment-10/data_agent_course.git
cd data_agent_course
git switch member-b-clean
```

后续提交和同步命令直接参考仓库 README。暂时不会 Git 的成员可先把本人模块、目录结构和运行记录交给集成人，开发继续推进。
